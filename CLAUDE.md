# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A stock symbol maintenance app for US markets (NASDAQ/NYSE/AMEX/OTC): a plain Node.js/Express backend, a no-build-step vanilla HTML/CSS/JS frontend, and PostgreSQL storage. Its purpose is upkeep of a symbol/company-name/market list — manual CRUD, bulk import, and automated drift-checking against Yahoo Finance — not trading or price data.

## Commands

```bash
npm install
npm start          # node server.js
npm run dev         # node --watch server.js
```

No test suite or lint script is configured.

The app is developed and run inside WSL (Linux), even though the project directory is on the Windows filesystem (`/mnt/c/Users/...` from WSL). Run all `node`/`npm`/`psql` commands from a WSL shell, not PowerShell.

**Node version matters**: WSL's Node is `/usr/local/bin/node`, managed by `n` (`n install 22` to upgrade); `/usr/bin/node` is an unrelated, ancient apt v12 - don't use it. Node **v22.7.0 specifically** has a JIT bug where, once code is hot, `Buffer.from(str, 'utf8')` and HTTP response bodies emit Latin-1 instead of UTF-8 for chars like `é` - so a long-running server started showing accented names (`Latécoère`, `Telefônica`) as `�` even though the DB was fine, and bulk scripts wrote real U+FFFD into the DB. `db.js` (loaded by the server and every script) refuses to run on v22.7.0, and `package.json` declares `engines: >=22.8.0`. If accented text ever looks garbled again, check the bytes the DB actually holds (`encode(convert_to(col,'UTF8'),'hex')`) before "fixing" data.

### Database

`sql/schema.sql` is the single source of truth for the schema and is written to be safely re-run after any change (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `DROP CONSTRAINT IF EXISTS` + re-add) — there is no migration framework, just re-apply this file:

```bash
psql -h localhost -U <role> -d <db> -f sql/schema.sql
```

PostgreSQL runs locally in WSL. The app connects over TCP (`localhost:5432`) with password auth via a dedicated role, not the `postgres` superuser and not peer auth — connection settings come from `.env` (see `.env.example`), read by `db.js`. `.env` also holds `SEC_EDGAR_CONTACT`, used only by `scripts/fill-cusip.js` (see below) as the required contact info in its SEC EDGAR requests' `User-Agent`.

### Routine data upkeep

The data drifts (renames, ticker changes, delistings, recycled tickers), and no single source catches everything - Yahoo in particular goes stale on recycled tickers. The workflow that has worked:
1. UI re-check button (or `check-stock-status.js` + `apply-update-candidates.js`): Yahoo name/market drift, with renames corroborated by NASDAQ Trader.
2. `node scripts/audit-stocks.js`, then review `exports/audit-report.csv` (gitignored - regenerated each run) by hand: symbol changes, delistings, names wrong in ways Yahoo agrees with. Verify each against Yahoo's last trade date / a successor search before applying; apply via `applyStockUpdate`, flag delistings with `isdelisted`.
3. `fill-company-details.js` / `fill-cusip.js` for gaps. Treat quantumonline CUSIPs for recycled tickers with suspicion.
4. `export-to-csv.js` and commit `exports/stocks.csv`.

## Architecture

**`stocks`** is the core table (`stock_symbol` UNIQUE, `company_name`, `exchange` free text — no longer a 4-value CHECK, `source` CHECK'd to `manual | yahoo | excel_import | nasdaq_trader`), plus extended company-info columns: `isdelisted` (bool, default false - set to true for stocks that stopped trading, *instead of* deleting them, so it's reversible and history survives; see `audit-stocks.js`), `category`, `cusips`, `sector`, `industry`, `currency`, `company_location`, `urll`, `description`, `ceo`. These are all nullable and optional, and deliberately **not** part of the web add/edit form itself (which only ever *submits* `stock_symbol`/`company_name`/`exchange`, unchanged from before) — but a manual add now auto-fills them a moment later; see the `POST /api/stocks` note below. `category` has no automated source anywhere and is manual/DB-only. `currency` is **always `USD`** (user-confirmed): every stock here trades on a US market, so it's a column default in `sql/schema.sql` and `lib/fillCompanyDetails.js` / `lookupStock` write `USD` rather than Yahoo's value - which followed the foreign listing whenever the details fallback was used (ULUCF got CAD from RME.V). Five auxiliary tables hang off `stocks`:
- `company_name_history` / `stock_symbol_history` — append-only audit log of renames, written transactionally, `stock_id` FK `ON DELETE CASCADE` (history disappears if the stock is later deleted).
- `stock_update_candidates` / `stock_removal_candidates` — a snapshot, not a log: `lib/checkStockStatus.js` (run by `scripts/check-stock-status.js` or the UI's re-check button) `TRUNCATE`s and fully repopulates both on every run; the button then applies and empties the update candidates. Also `ON DELETE CASCADE`, so deleting a stock that happens to be a removal candidate silently drops it from that list too.
- `stock_deletion_log` — the one exception: **no FK to `stocks`**, by design, since these rows must outlive the stock they describe.

**Two transactional diff-and-log mechanisms are the core non-obvious pattern**:
- **Updates**: `lib/applyStockUpdate.js` holds the shared core — `SELECT ... FOR UPDATE`s the current row, applies the update, diffs old vs. new `company_name`/`stock_symbol`, and conditionally inserts into the two history tables. It expects to run inside a transaction the *caller* owns (`BEGIN`/`COMMIT`/`ROLLBACK` + `client.connect`/`release`). Two callers use it: `PUT /api/stocks/:id` (one stock, from the web form) and `scripts/apply-update-candidates.js` (bulk, one candidate row at a time from `stock_update_candidates`). If you add a third way to update a stock, call this instead of re-inlining the diff logic.
- **Deletes**: `DELETE /api/stocks/:id` (`routes/stocks.js`) deletes the row (`RETURNING` its data) and inserts that data into `stock_deletion_log`, in the same transaction. Not yet extracted to `lib/` since there's only one caller.

Any future change to how stocks are updated or deleted needs to preserve these steps, since they're the only thing populating the history/log tables. Both paths sanitize text through a `Buffer.from(str,'utf8').toString('utf8')` round-trip before writing history rows (see `lib/sanitizeText.js` below).

**`source` tracks provenance**, not just for record-keeping: the "manual add log" UI section is literally `GET /api/stocks?source=manual`. Only `POST /api/stocks` (the web form) sets `source='manual'`; each of the import scripts stamps its own source value. If you add a new way to insert stocks, make sure it sets `source` correctly or it will silently pollute the manual-add log.

**Routes** (`routes/*.js`) are each mounted in `server.js` under their own path prefix (`/api/stocks`, `/api/company-name-history`, `/api/stock-symbol-history`, `/api/removal-candidates`, `/api/stock-deletion-log`). `routes/stocks.js` also owns `GET /api/stocks/by-symbol/:symbol`, used by every lookup-before-edit flow on the frontend (rename / change-symbol / delete-by-symbol forms all use a text input + shared `#stock-datalist` autocomplete, deliberately not a `<select>`, per prior feedback in this project). `GET /api/stocks/:id` (numeric id only) returns the full row including the extended detail columns. `GET /api/stocks/yahoo-lookup/:symbol` is a read-only `lookupStock` wrapper for the add form's pre-fill (404 if Yahoo has nothing). `routes/removalCandidates.js` also owns `POST /refresh` + `GET /refresh-status` for the re-check button (see `check-stock-status.js` below). `POST /api/stocks` returns 409 on a duplicate `stock_symbol` (the UNIQUE constraint is the real guard; the frontend also checks its loaded list first). `PUT`/`POST` on `routes/stocks.js` will accept the extended detail fields in the request body if given, but nothing in the frontend currently sends them - that path exists for completeness, not because anything calls it that way today.

**`POST /api/stocks` auto-fills extended details in the background.** When a manual add doesn't itself specify any of the extended detail fields (the normal case - the web form never does), `routes/stocks.js` responds with the newly-inserted row immediately (so the add stays fast/synchronous) and *then*, fire-and-forget via `autoFillNewStock()`, kicks off `lib/fillCompanyDetails.js` and `lib/cusipLookup.js` concurrently (`Promise.allSettled`, so one failing doesn't block the other) to fetch and write in the same data the bulk scripts would have produced by hand. Errors are only `console.error`'d on the server, never surfaced to the client - a failed auto-fill just leaves those columns `null`, exactly as if the script hadn't been run yet, and `scripts/fill-company-details.js`/`scripts/fill-cusip.js` (which both select "still-missing" rows by default) will pick it up on their next run regardless. If you add a bulk-insert path (an import script, say) that should get this same treatment, call `autoFillNewStock`-equivalent logic per row deliberately - don't let a bulk loop fire hundreds of these concurrently, since `lib/cusipLookup.js` hits two rate-limited external services.

**`lib/yahoo.js`** centralizes the `yahoo-finance2` client. `lookupStock(symbol)` returns `stock_symbol`/`company_name`/`exchange` (via `marketLabelForQuote(quote)`, which collapses Yahoo's finer-grained names like `NasdaqGS`/`NYSE American`/`OTC Markets OTCPK` to the short `NASDAQ`/`NYSE`/`AMEX`/`OTC` labels the rest of the table uses — `EXCHANGE_TO_MARKET` by code first, then a name-pattern fallback, and anything unrecognized passes through as Yahoo's `fullExchangeName`. `lib/checkStockStatus.js` compares with the same function, so those finer-grained names are not an `exchange_mismatch` (and for exchange-listed stocks, NASDAQ Trader's exchange overrides Yahoo's anyway - see the status-check notes below). Still free text, not a validation gate) plus best-effort extended fields from `fetchCompanyDetails()` (`sector`, `industry`, `currency`, `company_location`, `urll`, `description`, `ceo` — via `quoteSummary`'s `assetProfile`/`price` modules; `ceo` is picked from `companyOfficers` by matching a "CEO"/"Chief Executive" title; `company_location` is a full postal address composed from `assetProfile`'s `address1`/`address2`/`city`/`state`/`zip`/`country` - not just the country - via the module-local `composeAddress()`, which skips any piece that's missing, since non-US addresses usually have no `state`). `fetchCompanyDetails` never throws — a `quoteSummary` failure (e.g. for non-equity types) just leaves those fields `null` rather than failing the whole lookup. Yahoo doesn't expose CUSIP via these modules at all (it's licensed data from CUSIP Global Services, not something free financial APIs generally redistribute - OpenFIGI deliberately excludes it too).

**Symbol format: always go through `toYahooSymbol()`.** Our symbols follow the exchange/NASDAQ Trader convention for share classes and SPAC securities (`BRK.B`, `KCA.U` units, `NE.W` warrants, `CELG.R` rights); Yahoo writes them `BRK-B`, `KCA-UN`, `NE-WT`, `CELG-RI`. Querying Yahoo with our form returns nothing, which once put ~150 live stocks on the removal list and left their details/CUSIP unfillable. `lib/yahoo.js`'s `toYahooSymbol()` does the conversion; every Yahoo call (`lookupStock`, `fetchCompanyDetails`, `lib/checkStockStatus.js`'s batch quote + mapping results back) uses it, and `lookupStock` returns the symbol in *our* form. SEC's `company_tickers.json` uses the same dash form (so `lib/cusipLookup.js` converts for the CIK lookup), but quantumonline.com uses our dot form - don't convert there.

**`fetchCompanyDetails(symbol, companyName)`'s foreign-listing fallback**: many thinly-traded US OTC tickers are actually a foreign company's secondary/cross-listing - e.g. `ULUCF` (Roland Mineral Enterprises Corp., OTC Pink) has nothing under that ticker on Yahoo at all, but the same company trades as `RME.V` on the TSX Venture Exchange, which Yahoo has full data for. So when the direct `quoteSummary(symbol)` lookup comes back completely empty (and `companyName` was given - not every call site has one), `findAlternateSymbol()` calls Yahoo's `yf.search(companyName)`, takes the top `EQUITY` result, and requires its name to match `companyName` via `lib/normalizeCompanyName.js`'s `companyNamesMatch()` (which strips punctuation/legal-suffix noise) before trusting it - a loose or absent match is treated as "not found," never a guess. "Empty" means no *profile* - currency alone doesn't count, since Yahoo returns it from the `price` module even for a bare OTC stub (CHCRF / Cheelcare returned only "USD", which used to count as found and skipped the fallback to its TSXV listing CHER.V). When the fallback is used, the currency stays the original listing's if known. Only company details use this fallback; CUSIP lookup (`lib/cusipLookup.js`) doesn't, since it's tied to a specific filing/page for the original ticker, not the company generally.

**`lib/fillCompanyDetails.js`** wraps `fetchCompanyDetails` + the `UPDATE stocks SET sector = ..., ...` write (sanitizing text fields first - see `lib/sanitizeText.js` below) into one `fillCompanyDetails(pool, stock)` call, returning whether anything was written. The `UPDATE` uses `COALESCE(new, existing)` per field, so a field Yahoo happens not to return this time keeps its stored value rather than being wiped to null. Shared by `scripts/fill-company-details.js` (bulk backfill) and the `POST /api/stocks` auto-fill above, so the two paths can't drift.

**`lib/cusipLookup.js`** holds the SEC-EDGAR-then-quantumonline.com CUSIP lookup (see `scripts/fill-cusip.js` below for the source details) behind one `lookupCusip(symbol, { onSourceError })` call returning `{ cusip, source }`. It caches the SEC ticker→CIK map for the life of the process (an ~800KB file, no need to refetch per symbol). Shared by `scripts/fill-cusip.js` and the `POST /api/stocks` auto-fill above. Two past bugs shape it:
- **Only a 13G whose `SUBJECT COMPANY` header CIK is this company counts.** A company's EDGAR listing also holds 13Gs it filed *as a holder* of other companies; the old code took the newest one blindly and stored another issuer's CUSIP for JPM, GS, MS, BLK, AMGN, CMCSA, ARCC and more. Accessions starting with the company's own CIK (self-filed) are skipped without downloading; at most `SEC_MAX_DOCS` documents are checked. `scripts/recheck-sec-cusips.js` repaired rows written before this fix.
- **All SEC requests go through `secFetch()`**, which spaces them `SEC_MIN_GAP_MS` apart process-wide - SEC returned HTTP 429 to just 4 concurrent workers, and then blocks for ~10 minutes.
- **The header subject isn't enough either**: filers mis-tag it (Norges Bank's 13G "about" PLUG is about Rubrik; GSK's own 13G on its Wave stake names GSK as subject), and even with the right issuer they paste wrong CUSIPs (two of GROY's 13Gs print NexGen's). So the cover page's "(Name of Issuer)" must match the subject's header names (incl. former) or `companyName`, and the result is a **vote by issuer (first 6 chars) across up to `SEC_MAX_DOCS` filings, then that issuer's newest CUSIP** - plain majority picked pre-split numbers (SMCI, HTZ). A lone 1-vs-1 disagreement is "not found". Placeholders like `000000000` (which pass the check digit) are rejected by `isValidCusip`.
- **Some securities skip SEC entirely** (pass `listing` from `lib/nasdaqTrader.js` so it can tell): preferreds/notes/warrants/units/rights (`isNonCommonSecurity` - SEC's ticker map points them at the parent's CIK, whose 13Gs are about the common, so they all got the common's CUSIP), and any class of a multi-class company (`hasCommonSibling` - FOX/FOXA, UHAL/UHAL.B; the 13Gs don't say which class). quantumonline (keyed by ticker) handles those, but it's stale after reorganizations: for NWS/NWSA, LBTYA/B/K, BATRK and FWONA/FWONK it returned pre-reorg CUSIPs, and those groups still share one stored CUSIP pending a manual fix.
- **Callers must run `findCusipConflict(pool, cusip, { stockId })` before writing**: two of our symbols never share a CUSIP, and quantumonline's own pages carry other companies' CUSIPs (CSQR shows Copart's, TELO Outset's, KLAR Ategrity's), which no name check can catch. A value another stock already holds is not written (logged instead) - it doesn't guess which side is right. `fill-cusip.js` and the add auto-fill both do this. `scripts/fix-cusip-conflicts.js [--plan file.json] [--apply]` was the one-off repair for values written before these rules.
- quantumonline's no-match page says `Not Found!`; don't loosen that to `/not found/i` - bank pages contain "Not found in FDIC" next to a real CUSIP. Its data can be stale (BLK still shows the pre-2024-reorg `09247X101`), and since it's keyed by ticker, a recycled ticker can return the *previous* issuer's CUSIP (FGC) - don't overwrite a stored CUSIP with a quantumonline value just because they differ. So `lookupCusip(symbol, { companyName })` - pass it whenever known (the add auto-fill, `fill-cusip.js`, `recheck-sec-cusips.js` all do) - only trusts a quantumonline CUSIP when the security name printed before "Ticker Symbol:" on the page contains the first distinctive word of `companyName`; FGC's page names a NextEra Energy bond, so it's rejected for FG Nexus.

**`lib/validateCusip.js`** implements the real CUSIP check-digit algorithm (`isValidCusip(value)`) - a 9-character CUSIP's last character is a check digit computable from the first 8, so this catches typos without needing to look anything up externally. `routes/stocks.js` calls it to reject a malformed `cusips` value on `POST`/`PUT` with a 400; `lib/cusipLookup.js` calls it to sanity-check whatever either source's page parsing produced before returning it.

**`lib/sanitizeText.js`** is the `Buffer.from(str,'utf8').toString('utf8')` round-trip that turns invalid/unpaired UTF-16 (occasionally seen in text from external APIs) into valid UTF-8 before it hits Postgres, which otherwise rejects the whole `INSERT`/`UPDATE` with "invalid byte sequence for encoding". Shared by `lib/applyStockUpdate.js`, `lib/checkStockStatus.js`, and `lib/fillCompanyDetails.js`. During initial development of the auto-fill/backfill scripts, 267 stocks' worth of Yahoo data was silently lost to that Postgres error; the underlying cause was most likely the Node v22.7.0 bug described under Commands (hot `Buffer.from` emitting Latin-1 bytes), not bad API text - on that Node version this round-trip only turned the error into stored `�`. Keep calling it on new write paths for API-sourced text, but the real protection is not running v22.7.0.

**`lib/nasdaqTrader.js`** loads NASDAQ Trader's daily symbol directory (`symbol -> { name (raw), exchange }`, ETFs kept, test issues dropped) for `lib/checkStockStatus.js` and `scripts/audit-stocks.js`. `scripts/import-nasdaq-trader.js` keeps its own parser since it filters ETFs out for inserting.

**`lib/normalizeCompanyName.js`** also exports the cross-source helpers `issuerKey` (issuer-only fingerprint: drops parentheticals, coupon terms like "5.25% Senior Notes…", and ADR/ordinary-share/legal-form descriptors), `isTruncationOf` (our ~30-char name is a literal mid-word prefix of the full one), and `sameCompany` (any of those or `companyNamesMatch`). Use `sameCompany` when asking "do two *sources* mean the same issuer?"; keep `companyNamesMatch` for "did the name change?".

**`lib/normalizeCompanyName.js`** vs. **`lib/cleanSecurityName.js`** solve two different problems and are not interchangeable:
- `normalizeCompanyName` collapses a name to a lossy comparison fingerprint (drops accents via NFD + `\p{M}`, a *trailing* ` New` re-listing tag - trailing only, or "New Jersey" breaks - and noise words including warrant/unit/right tags like Yahoo's ` WT`, then *all* whitespace - so `Telefonica` vs `Telefônica` or `GameStop Corporation` vs `GameStop Corp. WT` is not a rename) — used only by the status checker to decide whether two names are "the same" (e.g. NASDAQ Trader's "JP Morgan Chase & Co. Common Stock" vs. Yahoo's "JPMorgan Chase & Co." must compare equal).
- `cleanSecurityName` produces a real display name by stripping the trailing security-type descriptor (" Common Stock", " - Class A Ordinary Shares", " Depositary Shares, each representing...", etc.) while keeping normal spacing (the descriptor must start at a word boundary - without it "Curtiss-Wright" came out as "Curtiss-W") — used when *writing* `company_name` (`scripts/import-nasdaq-trader.js` and the one-off `scripts/clean-company-names.js`), not for comparison.

**`scripts/`** are standalone maintenance tools that talk to Postgres directly (each does its own `require('../db')` + `dotenv.config()`) and are meant to be run from the CLI, independent of the running server — not exposed through the web UI or API by design (the one exception is `check-stock-status.js`, see below):
- `add-from-yahoo.js SYMBOL...` — look up and insert specific symbols.
- `import-from-excel.js <path.xlsx>` — bulk import from a spreadsheet (header aliases are matched loosely; later duplicate rows for the same symbol win).
- `import-nasdaq-trader.js` — downloads NASDAQ Trader's official listing files and bulk-inserts all NASDAQ/NYSE/AMEX securities, cleaning names via `cleanSecurityName` on the way in. Does **not** cover OTC (that data isn't in an exchange-listing feed); OTC coverage currently comes only from Excel imports.
- `clean-company-names.js` — one-off backfill that re-runs `cleanSecurityName` over every existing row and updates `company_name` where it changed. Does **not** touch `company_name_history` — this is a data-quality fix, not a rename, so it shouldn't show up as one.
- `check-stock-status.js` — a thin CLI wrapper around `lib/checkStockStatus.js`, which is also run from the web UI's removal-candidates "重新檢測/Re-check" button via `POST /api/removal-candidates/refresh` (runs in the background, one at a time, with process-local state; the UI polls `GET /api/removal-candidates/refresh-status` every 3s and reloads the list when done - a full run takes ~15-30s). **The button also applies the update candidates right after** via `lib/applyUpdateCandidates.js` (same as `apply-update-candidates.js`, so renames still land in the history tables) - per the user, a re-check should update changed stock info directly, not just list it. So after a button run `stock_update_candidates` is normally empty; the CLI script still only checks. Removal candidates are never auto-applied. It batches all DB symbols through `yf.quote()` (200 at a time) and rebuilds the two candidate tables (`TRUNCATE` + full repopulate, so it's always a fresh snapshot, not additive). Pass `{}, { validateResult: false }` as `yf.quote()`'s 3rd arg, or one malformed instrument in a batch of 200 silently drops the entire batch. **Yahoo's names are not trusted alone for exchange-listed stocks**: Yahoo keeps serving a recycled ticker's *previous* owner's name (DPU read "DB Commodity Long ETN" long after becoming Top KingWin; RCD still read as an Invesco ETF), and most of our names were originally copied from Yahoo, so "Yahoo agrees with us" is not independent confirmation. So for NASDAQ/NYSE/AMEX stocks, a rename is only proposed when NASDAQ Trader's listing (`lib/nasdaqTrader.js`) also matches Yahoo's new name (via `sameCompany`) and doesn't already match ours; one missing from the listing gets no rename at all. OTC has no second source, so it stays Yahoo-only. Without this, the button would revert names corrected from the official listing. **Exchange changes follow the same principle** (`corroboratedExchange`): for a symbol in the listing, the listing's exchange wins and Yahoo's is ignored (Yahoo put EVV on NYSE when it's NYSE American, and the button applied it); a listed stock missing from the listing may only move to `OTC`; OTC stocks use Yahoo. **Failure modes are conservative too**: if the listing can't be downloaded, NASDAQ/NYSE/AMEX stocks get *no* name/market suggestions that run (never a silent Yahoo-only fallback, which the button would auto-apply); if every Yahoo batch fails, `checkStockStatus` throws before `TRUNCATE`, leaving the previous candidate lists intact. Its result carries `failedBatches` / `listingAvailable`, which the UI and CLI show as warnings. A stock whose market *and* name both changed gets one candidate row carrying both, and an OTC stock that appears in the listing (uplisted) takes the listing's exchange. The rules are covered by a 27-case simulation (fake Yahoo / listing / DB, stubbing `yf.quote` and `loadNasdaqTraderListing` before requiring `lib/checkStockStatus.js`) that was run ad hoc - there's no test suite to keep it in; rebuild one along those lines when changing these rules. **Removal candidates likewise**: a symbol on NASDAQ Trader's listing is never a removal candidate, whatever Yahoo says - Yahoo lacks some (FBYDP, NE.A) and labels closed-end funds / baby bonds `ETF` (FSSL, SWZ, SCCD). For OTC, "not on Yahoo" is weak evidence: Yahoo's small-OTC coverage is poor (ULUCF traded on 2026-09-29 but isn't on Yahoo at all). OTC Markets' own site backend (`https://backend.otcmarkets.com/otcapi/stock/trade/inside/<SYM>?symbol=<SYM>` and `.../company/profile/full/<SYM>?symbol=<SYM>`, needs a browser-like `Origin`/`Referer: https://www.otcmarkets.com`) answers 404 for symbols that no longer exist and gives last trade/quote dates otherwise - it was used by hand (paced 500ms) to settle the OTC removal list, but isn't wired into the code; it's an unofficial endpoint, so ask before automating it. After changing these rules, **restart the server** - the button runs the code loaded at startup, and a stale process once kept running the pre-corroboration checker. Rename suggestions only ever use Yahoo's `longName`, never `shortName` (a 31-char truncation like "Ocean Capital Acquisition Corpo" or an abbreviation) - the button auto-applies suggestions, so a bad one directly corrupts `company_name`. A quote with no exchange info at all (seen with BF.A) is treated as unknown, not an `exchange_mismatch` - `suggested_exchange` is NOT NULL, and one such row used to roll back the whole write. Update candidates use reason `exchange_mismatch` (was `market_mismatch`) or `company_name_mismatch`; removal candidates use `not_found_on_yahoo` or `no_longer_equity` only — `unsupported_exchange` no longer exists as a reason since `exchange` is free text now, so nothing is "unsupported". Re-run this after any bulk company-name cleanup, since messy names inflate false-positive `company_name_mismatch` candidates.
- `apply-update-candidates.js` — thin CLI wrapper around `lib/applyUpdateCandidates.js` (shared with the re-check button). Reads every row out of `stock_update_candidates` and applies it to `stocks` via `applyStockUpdate` (so it still gets logged to history), then deletes the row it just applied. Only touches `stock_update_candidates`; `stock_removal_candidates` is intentionally left alone since deleting stocks is a separate, more consequential decision the UI leaves to a human.
- `fill-company-details.js [SYMBOL...]` — backfills the extended detail columns via `lib/fillCompanyDetails.js` (see above). With symbols given, only those; with none, every stock missing *any* of the 7 detail fields (not just `sector` - many stocks have a sector but no CEO/description/address) - a fresh manual add auto-fills this itself now (see the `POST /api/stocks` note above), so this script is mainly for catching whatever that auto-fill missed the first time (Yahoo having nothing that moment, a transient error, etc.) or backfilling stocks inserted by something other than the web form.
- `fill-cusip.js [SYMBOL...]` — the one exception to "everything talks to Yahoo or NASDAQ Trader": CUSIP isn't in Yahoo's API or NASDAQ Trader's listing files at all, so this uses `lib/cusipLookup.js` (see above), which tries two sources per symbol, in order:
  1. **SEC EDGAR** — every Schedule 13G/13G-A filed about a company prints "CUSIP No. ..." on its cover page, official U.S. government data with zero licensing ambiguity. Maps ticker → CIK via SEC's own `company_tickers.json`, lists that CIK's `SC 13G` filings via `browse-edgar`'s atom output, takes the most recent accession's full-submission `.txt`, and regexes out the CUSIP (normalizing `&nbsp;`/`&#160;` and stripped tags first, since different filers format the cover page differently - this is exactly what caught a real bug during development, where MSFT's filing used `&#160;` and silently fell through to source 2 until the regex was fixed). **Requires `SEC_EDGAR_CONTACT` in `.env`** (a real, identifiable email) - SEC 403s every automated request without one in the `User-Agent`, per https://www.sec.gov/os/webmaster-faq#developers; ask the user before hardcoding a value here, since it's their contact info going to a third party on every request. Not every company has a 13G on file (nothing has crossed the 5% institutional-ownership threshold), so this misses some symbols - that's expected, not a bug.
  2. **quantumonline.com** — a free public securities-lookup site (`search.cfm?tickersymbol=<symbol>&sopt=symbol`), used as the fallback for whatever SEC didn't have. No bulk API, and per its `robots.txt`/pages checked, no terms explicitly barring this, but it's still a small site - `QOL_DELAY_MS` (default 500ms) paces requests between symbols; don't lower it for bulk runs.

  With symbols given, only those; with none, every stock where `cusips IS NULL`.
- `recheck-sec-cusips.js [--apply]` — one-off repair for CUSIPs written before `lib/cusipLookup.js` checked the 13G's subject company (see above). For each stock with a CUSIP and a CIK, re-derives the filing the old code would have used; only if that wasn't about the company itself *and* the stored CUSIP is exactly the one that wrong filing yields does it re-look-up with the fixed logic and overwrite (possibly with null) - so values corrected by hand (e.g. JPM `46625H100`, BLK `09290D101`, where quantumonline is stale) are never clobbered. Sequential with backoff on SEC 429s, and writes each fix immediately so an interrupted run keeps its progress. Dry run unless `--apply`.
- `audit-stocks.js [--out path.csv]` — **read-only** cross-check of every non-delisted stock against NASDAQ Trader's listing, SEC's `company_tickers.json`, and Yahoo, writing findings to `exports/audit-report.csv`. Catches what the Yahoo-only status check can't: symbol changes (our symbol gone from the listing, same company listed under a symbol we don't hold - e.g. BRR→SVIA, DOMO→HUCK, HVII→ONEN; successors that are just the same issuer's other securities, like `SBXD`→`SBXD-UN`, are filtered by `symbolRoot`), delistings, truncated names, and name mismatches. A name mismatch is only reported when two sources agree with each other against us, since each source alone is noisy (formatting, stale data). Its output needs human review - it never writes. Symbol changes / renames found this way should be applied via `applyStockUpdate` (history), and delistings by setting `isdelisted = true` rather than deleting (reversible, keeps history); `isdelisted` rows are skipped by later audits.
- `export-to-csv.js` — (format lives in `lib/stockCsv.js`, shared with the stock list's **"匯出 CSV / Export CSV" button**, which calls `GET /api/stocks/export.csv?market=&q=` with the list's current filters - `buildStockFilter()` in `routes/stocks.js` is shared by the list and the export, so the file is always exactly what's on screen; it's sent with a UTF-8 BOM so Excel shows accented names, as `stocks_<market|all>[_<q>]_<date>.csv`. Descriptions contain newlines inside quoted fields, so count records with a CSV parser, not `wc -l`.) Dumps the full `stocks` table (including the extended detail columns) to `exports/stocks.csv` (committed to the repo, not gitignored). Re-run and re-commit after any bulk data change if you want the export to stay current; nothing does this automatically.

**Frontend** (`public/`) is a multi-page no-bundler setup: `index.html` + `app.js` is the main maintenance UI, and `stock.html` + `stock.js` is a separate, standalone per-stock detail page. Notable patterns to follow if extending it:
- i18n is a `TRANSLATIONS` object (zh/en) applied via `data-i18n` / `data-i18n-placeholder` attributes and a `t()` lookup — not a library. `stock.js` keeps its own small copy of this pattern rather than sharing `app.js`'s object, consistent with this codebase's general preference for per-page duplication over shared abstraction.
- Every list section (stock list, company-name history, symbol history, manual-add log, removal candidates, deletion log — 6 total) paginates client-side at `PAGE_SIZE = 15`, each with its own page-state variable and render function, duplicated per-section rather than abstracted into a shared helper. The two history API endpoints used to `LIMIT 200`; that cap was removed once pagination existed, so don't re-add a server-side limit without also handling it client-side.
- The three lookup-before-edit forms (rename, change-symbol, delete) each follow the same shape: a symbol input with datalist autocomplete, a "查詢/Lookup" button that `GET`s `by-symbol` and disables/enables the rest of the form, a "清空/Clear" button that calls that form's `reset*Form()`, and a submit that does the actual `PUT`/`DELETE`. Copy this shape rather than inventing a new one if adding a fourth.
- Stock-symbol inputs use `class="uppercase"` (CSS `text-transform`, display-only) rather than mutating the input value on keystroke.
- The add/edit form (`#stock-form`) is unchanged from before this app grew the extended detail columns: it still only has `stock_symbol`/`company_name`/`exchange` (the last now a free-text input with an `#exchange-datalist` built client-side from distinct values already in the list, replacing the old 4-option `<select>`). The stock list's **market filter** (`#market-filter`) is the opposite: a `<select>` with a fixed "全部市場/All Markets" (`value=""`) first option plus one option per market present, rebuilt in `populateStockDatalist()` from the full unfiltered list. It used to share the datalist input, but once it held "OTC" the browser only suggested values matching "OTC", so there was no way back to all markets without clearing the box - don't turn it back into a datalist input. It deliberately does **not** expose the extended detail fields as inputs - the server auto-fills them a moment after a manual add instead (see the `POST /api/stocks` note above), so a freshly-added stock's `/<symbol>` detail page fills itself in within a second or two of adding it, with no separate step needed.
- **Per-stock detail page**: clicking a stock's symbol in the list (`public/app.js`'s `renderTable`) is a plain `<a href="/<lowercase-symbol>">`, e.g. `/aapl` - a real, bookmarkable/shareable URL, not a JS modal. `server.js` serves this via a catch-all `app.get(/^\/[A-Za-z.-]{1,50}$/, ...)` (placed after `express.static` and the `/api/*` routes, so it only fires when no static file matched, and its regex - one path segment, no slashes - can't shadow `/api/*`) that always returns `public/stock.html`. That page's `stock.js` reads the symbol straight from `location.pathname`, calls `GET /api/stocks/by-symbol/:symbol`, and renders the full company-info record read-only, or a "not found" message on 404. If the stock was created within the last 2 minutes and `sector`/`cusips` are still empty, it re-fetches every 3s (max 10 times) so the background auto-fill shows up without a manual reload - the add form's success message links straight here.
- **Add-form pre-fill**: in add mode, committing a symbol (`change` event - blur/Enter, not per keystroke) first warns if it's already in the list (same duplicate warning + detail-page link as on submit), otherwise calls `GET /api/stocks/yahoo-lookup/:symbol` and fills in company name / market. Despite the route name it applies the status checker's trust rules: for a symbol on NASDAQ Trader's listing (`getCachedListing()`, cached 1h), the listing's exchange wins and Yahoo's name is used only if it matches the listing's (else the cleaned listing name) - Yahoo alone would pre-fill a recycled ticker's previous owner (DPU). Listed symbols Yahoo won't return (closed-end funds it calls ETFs) still pre-fill from the listing; the response's `source` (`nasdaq_trader`/`yahoo`) is shown in the hint.
- **Duplicates by equivalent spelling**: `BRK-B`, `brk.b` and `BRK.B` are the same security (`symbolsEquivalent` in `lib/yahoo.js`), but the `UNIQUE` constraint only sees exact spellings. `routes/stocks.js`'s `findEquivalentStock` checks this in the pre-fill lookup, `POST` and `PUT` (symbol change), answering 409 with `existing_symbol` = the spelling we hold, which the frontend's duplicate warning links to. It only overwrites those inputs if they're empty or still hold what the previous lookup put there, never something the user typed. Nothing is written until the user presses Add.
- **Add-form messages**: `#form-error` shows the duplicate-symbol warning (built with DOM nodes, not `innerHTML`, since it embeds a `/<symbol>` link) both from the client-side list check and from a 409; `#form-hint` shows neutral status - Yahoo lookup progress, and after a successful add "已新增 X … 查看：X" linking to the new stock's detail page.
