# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A stock symbol maintenance app: a plain Node.js/Express backend (JSON API), a **React (create-react-app) + Tailwind CSS** frontend in `client/` (built by `npm run build` into `client/build`, served by Express), and PostgreSQL storage. Its purpose is upkeep of a symbol/company-name/market list - browsing, manual add/update, bulk import, and auto-filling company details/CUSIP - not trading or price data.

**The data lives in someone else's table.** Since 2026-10-06 the app reads and writes the existing shared table `test.company_profiles` in the remote database `waffle_test` (~79k rows: every market, not just US; ~44k delisted). Per the user: **never change its columns, and only SELECT / INSERT / UPDATE - no DELETE.** The login role (`victor`) also can't create tables anywhere (no CREATE on `test` or `public`), so the app has no tables of its own. Earlier the app owned a local WSL database with a `stocks` table plus history/candidate/deletion-log tables; those features (delete, deletion log, rename/symbol history, manual-add log, Re-check + removal candidates) were removed in this switch - see git history before that change if one ever has to come back (it would need tables a DBA creates; `sql/ddl_test_schema.sql` holds that DDL).

If accented text ever looks garbled again, check the bytes the DB actually holds (`encode(convert_to(col,'UTF8'),'hex')`) before "fixing" data.

### Database

Connection settings come from `.env` (gitignored; see `.env.example`), read by `db.js`: `PGHOST`/`PGPORT`/`PGUSER`/`PGPASSWORD`/`PGDATABASE`, plus `PGSCHEMA=test`, which `db.js` turns into the connection's `search_path` - every query uses unqualified table names. `.env` keeps the old local-DB settings commented out. `HOST` (listen address, default `0.0.0.0`) is read by `server.js`, which serves the API (`/api/stocks`, `/api/monitor`, and `GET /api/health` - a DB-free liveness check used by `deploy/remote.sh`) and the frontend (below). The frontend calls the API with relative `/api` URLs. A leftover `PUBLIC_URL` in an existing `.env` is ignored. The WSL IP can change after a WSL restart or reboot. `.env` also holds `SEC_EDGAR_CONTACT`, the required contact info in SEC EDGAR requests' `User-Agent` (see `lib/cusipLookup.js`).

The role can't read most of `pg_catalog` (`pg_namespace`, `pg_tables` -> permission denied); use `information_schema`, `has_*_privilege()` and `to_regnamespace()` to inspect. That also breaks some SQL that silently qualifies into `pg_catalog`: **explicit casts (`$1::varchar`) and `substring(x from y)` fail with "permission denied for schema pg_catalog"** - avoid them. And a parameter used both as an `INSERT ... SELECT $1` value and in a `WHERE` comparison fails with "inconsistent types deduced for parameter" - pass the value twice as separate parameters instead (the import scripts do).

`company_profiles` has triggers `company_profiles_audit` (insert/update/delete) and `tr_updated_at_company_profiles`. The audit trigger runs `sandbox.audit_company_profiles()`, which inserts into `sandbox.audit_company_profiles` - a schema `victor` can't even list. Until the DBA granted access (2026-10-06), every INSERT/UPDATE failed with "permission denied for schema sandbox" (the web add showed "internal server error"); if that error comes back, it's this grant, not the app. The user's intent is that only `test` is used. `sql/schema.sql` describes the old local schema and is not used against this database.

## Architecture

**`lib/stockTable.js` is the single place that knows the table.** `TABLE` (`company_profiles`), `ID` (`company_profile_id`), `SELECT_COLUMNS` (aliases `company_profile_id AS id` and `companysite AS urll`, so the API keeps the field names it had), `writeColumn()` (API field -> real column for writes), `isBlank()` and `PREFERRED_ORDER`. Every query in `routes/`, `lib/` and `scripts/` goes through these - don't hardcode the table or the column names elsewhere.

**What the table's data is like** (shapes several rules below):
- `stock_symbol` is **not unique** (~200 symbols have several rows): a recycled ticker keeps the old company's row (`isdelisted = true`, `display_security = 'false'`) next to the new one. `PREFERRED_ORDER` (live first, then `display_security = 'true'`, then newest id) picks one row when only a symbol is known. The unique index `idx_unq_company_profiles_stock_symbol` is on **`(stock_symbol, company_name)`** (definition not readable by this role; a 23505's `detail` showed it on 2026-10-07), so inserts - and renames - can hit 23505 -> answered 409 "stock_symbol already exists" (e.g. ADCT's live row 124802 "Adc Therapeutics S.A." can't become "ADC Therapeutics SA", which the old delisted row 8837 already is). `symbolNameTaken()` in `routes/stocks.js` turns that particular 23505 into a 409 with `code: 'symbol_name_taken'`, `existing_id`, `existing_symbol`, `existing_delisted`; the forms translate it and link to that row (`LookupEditForm` / `StockFormPanel`: `symbolNameTaken`; a plain 409 is `symbolInUse` for a symbol change, `duplicateSymbol` for an add); import scripts use `INSERT ... SELECT ... WHERE NOT EXISTS` rather than `ON CONFLICT (stock_symbol)`, which needs a matching non-partial constraint.
- Symbols span markets: digits and `. - _ ^ = &` and spaces (`000001.SZ`, `3-Jun.DE`, `^GSPC`); a few are mixed-case (`ACIC_old`). `SYMBOL_PATTERN` in `routes/stocks.js` allows these; lookups are case-insensitive and never uppercase stored values. New symbols (add, symbol change) are still uppercased; the edit form only sends `stock_symbol` when it actually changed, so saving a mixed-case row doesn't rename it.
- `exchange` has ~157 distinct free-text values (NASDAQ, NYSE, OTC, PNK, LSE, Tokyo, ...) and can be NULL or `''`. Missing values generally are a mix of NULL and `''` - `isBlank()` / `NULLIF(col, '')` treat both as missing.
- `currency` varies (USD, EUR, CNY, GBp, ...). `fillCompanyDetails` only fills it when empty, taking Yahoo's value - it is no longer forced to `USD` (that rule was for the old US-only table).
- `cusips` can hold several space-separated values, and the same CUSIP appears on several rows (old delisted row + current row). `findCusipConflict` therefore matches within the list and ignores delisted rows.
- `isdelisted` is nullable (use `coalesce(isdelisted, false)`).
- **Some stored text is mojibake** (UTF-8 bytes decoded as Latin-1/cp1252 by whatever wrote it - possibly the Node v22.7.0 bug below), found 2026-10-07 with the pattern `Ã[-¿]|â€|Â[-¿]`: `company_location` 243 rows ("SÃ£o Paulo", "NykÃ¶ping"), `ceo` 12 ("JosÃ©"), `description` 182 ("â€™"); `company_name` and the other columns 0, and no U+FFFD or CJK text anywhere. **Leave it as is** - the user decided (2026-10-07) that mojibake stored in the data is acceptable: it's the data, not the UI. Don't repair it unless asked. A plain `Ã`+letter ("SÃO") is legitimate uppercase text, not mojibake.

**Routes**: `routes/stocks.js` (at `/api/stocks`) and `routes/monitor.js` (at `/api/monitor`, see the stock monitor below). There is deliberately **no DELETE route**.
- `GET /` is paginated on the server (`?page=&pageSize=`, max 100; answers `{ rows, total, page, pageSize }`) - the table is far too big to send whole, so a client must page through it. `buildStockFilter()` (`?market=&q=`, `q` LIKE-escaped) is shared with `GET /export.csv` so the export is exactly the filtered list (all pages).
- `GET /markets` (distinct exchanges, e.g. for a market filter or market suggestions) and `GET /suggest?q=` (20 symbols by prefix, for symbol autocomplete - the table is too big to preload).
- `GET /by-symbol/:symbol` (case-insensitive; exact-case match first, then `PREFERRED_ORDER`) and `GET /:id` both return `SELECT_COLUMNS` plus the in-process auto-fill report if any.
- `GET /yahoo-lookup/:symbol` - pre-fill for an add: first reports an existing live row (409 with `existing_symbol`), else returns company name / market and `source` (`nasdaq_trader`/`yahoo`). Despite the route name, for a symbol on NASDAQ Trader's listing (`getCachedListing()`, cached 1h) the listing's exchange wins and Yahoo's name is used only if it matches the listing's - Yahoo keeps a recycled ticker's previous owner's name (DPU came back as "DB Commodity Long ETN"). Nothing is written.
- `POST /` / `PUT /:id` - add / update. `PUT` goes through `lib/applyStockUpdate.js` (one `UPDATE ... RETURNING`; no history tables any more - the table's audit trigger records changes). If you add another way to update a stock, call it rather than re-inlining the column mapping.

**Duplicates**: `findEquivalentStock` (pre-fill lookup, `POST`, `PUT` symbol change) treats `BRK-B`, `brk.b` and `BRK.B` as the same security (`symbolsEquivalent` in `lib/yahoo.js`) and only considers **non-delisted** rows, so a recycled ticker's new owner can be added next to the old delisted row. Answers 409 with `existing_symbol` (the spelling actually held, e.g. `BRK.B` when `BRK-B` was sent).

**`POST /api/stocks` looks up the extended details before answering, and says why anything is missing.** When a manual add doesn't itself specify any of the extended detail fields (the normal case - the old web form never did), `routes/stocks.js` inserts the row, then runs `autoFillNewStock()` - `lib/fillCompanyDetails.js` and `lib/cusipLookup.js` concurrently (`Promise.allSettled`, so one failing doesn't block the other) - and **waits for it** (per the user: an add should come back with everything it can find, not fill in later), up to `ADD_LOOKUP_TIMEOUT_MS` (20s; past that it answers `autofill: { pending: true }` and the lookup finishes in the background). The response is the re-read row plus `autofill`, a report of each part's outcome: `details` `filled | not_found | error`, `cusip` `filled | not_found | conflict | error` with `lookupCusip`'s per-source `reasons` codes (SEC `no_cik` / `no_13g` / `skipped_non_common` / `skipped_multi_class` / ..., quantumonline `not_found` / `name_mismatch` / ...) or the `conflict_symbol` already holding that CUSIP, plus `next_retry_at` / `retries_exhausted`. `GET /:id` and `GET /by-symbol/:symbol` return the same report while it is in memory, so a client can show why fields are missing and re-fetch right after `next_retry_at`. Anything `not_found` / `error` is **retried after 1, 5, 15 and 60 minutes** (`AUTO_FILL_RETRY_MS`; re-reads the row first, stops once filled); a CUSIP conflict isn't retried - it needs a human. A brand-new listing often isn't in the sources yet at add time (VYLR had no Yahoo profile when added, a full one hours later; SEC has no 13G for a new issuer). Yahoo returning only `currency` counts as nothing found. Reports and retries are in-process, so a server restart drops them, and `scripts/fill-company-details.js`/`scripts/fill-cusip.js` pick up whatever is still empty. If you add a bulk-insert path that should get this treatment, run it per row deliberately - don't fire hundreds concurrently, since `lib/cusipLookup.js` hits two rate-limited external services.

**Stock monitor (`lib/stockMonitor.js`)** - the automatic "detect and update" job the user asked for: checks every row (all markets, per the user) against NASDAQ Trader's listing + Yahoo quotes (batched 200, ~5 min for 79k rows) and **never deletes**. Run through the API (`POST /api/monitor/run { apply }`, poll `GET /api/monitor/status`, items from `GET /api/monitor/report`; state in-process in `routes/monitor.js`), from `scripts/monitor-stocks.js [--apply] [--list] [SYMBOL...]` (preview unless `--apply`), and daily via `MONITOR_DAILY_AT=HH:MM` in `.env` (03:00 Asia/Taipei is set; `scheduleDaily()` in `routes/monitor.js`, needs the server running at that time). Rules live in the pure `planRow(row, ctx)` (a 20-case fake-data check was run ad hoc - rebuild one when changing them):
- Status: in the listing or Yahoo last trade <= 30 days -> listed; Yahoo last trade >= 120 days -> delisted; a plain-symbol NASDAQ/NYSE/AMEX row missing from both listing and Yahoo -> delisted; anything else (thin OTC, failed Yahoo batch, preferreds absent from the listing) -> unknown, untouched. A delisted row is revived only if the current name is the same company and no other live row holds the symbol (recycled tickers). The first preview showed ~26k rows to revive, ~23k of them non-US that the table had flagged delisted (likely another system's "not tracked"); the user chose all markets anyway.
- Name: listed symbols need listing + Yahoo agreement; otherwise Yahoo `longName`. Placeholder names (`324823`, `...missing co name`, `eo_company`, empty) are always replaced. Since 2026-10-06 (the user: names should match the correct name as closely as possible; a preview had 1,072 "name differs" notes, mostly false) the comparison is `sameName = sameCompany || similarNames` (`lib/normalizeCompanyName.js`: drops generic words - ETF/ETN/Fund/Shares/Trust/Series/Index/Inc/Corp/... - and maps Exchange-Traded Notes->ETN, U.S.->US, &->and, J.P.->JP, -3x->-3, Public Limited Company->plc; a word may be a prefix of the other, NYLI/NYLIM). Listing + Yahoo agreeing makes the name corroborated; the name written is Yahoo's (clean form shown on Yahoo; fund-family prefix like "Roundhill ETF Trust - " dropped when the rest matches the listing), with words spelled as in the listing where only the case differs (NVDA, MicroSectors), or the listing's full name when Yahoo cut it mid-word ("... ETF - Se"). Then, in order: a listed row whose stored name has a fund-family prefix or is a word-by-word abbreviation of the current one ("Etracs Alerian Mlp Ind Ser B") is corrected; corroborated -> written; a stored name cut off mid-word that the listing continues ("KKR ... LLC 4.") gets the listing's full name; Yahoo confirming the stored name while the listing's is only a less specific form -> nothing; Yahoo's ~30-char fund abbreviation of our name ("Brown Capital Mgmt Small Co Inv") -> nothing (noted if it doesn't fit - maybe a rename); otherwise noted. A 30/31-char Yahoo name counts as truncated only if it doesn't end like a complete name (Inc/Ltd/Limited/Association/Corp. III/...). Names 1-2 characters apart (a source's typo: "ETFo", "Holdlings") are never changed. When the names are the same but spelled differently and corroborated, the sources' spelling is written ("Adc Therapeutics S.A." -> "ADC Therapeutics SA"), unless that only makes it >5 chars longer ("... ETF ETF Shares", "Plc" -> "Public Limited Company"). `cleanSecurityName` also strips more listing descriptors ("Ordinary Shares, no par value", "Subordinate Voting Shares", "Common Stock, $0.01 par value", "Common Units ...", "due January 8, 2038", "ADS"/"ADR"/"Unsponsored", "(New)", "D/B/A ", "X Trust Shares of Y", a name repeated twice). Checked by running old vs new `planRow` on the same full-table data: every rename the old code made is kept, notes went 1,073 -> 337, renames 26 -> 249 (each reviewed). The monitor's name rules are the only users of `similarNames` & co.; `sameCompany` itself is unchanged.
- Market: listing's NASDAQ/NYSE/AMEX wins; a US row Yahoo now shows on OTC -> `OTC`; non-US only filled when empty. `marketOf()` collapses PNK/OEM/NYQ/... spellings.
- Category (OTC only): Yahoo `fullExchangeName - quoteSourceName - exchange`, e.g. `OTC Markets OTCPK - PNK` / `OTC Markets OTCQX - Delayed Quote - OQX`; set when empty or when an existing `OTC Markets ...` value has a different tier/code (quoteSourceName flickers, so it's ignored in the comparison). Other category styles (`Domestic Common Stock`, `ETF`) are left alone.
- **Rename blocked by the unique index** (another row with the same symbol already has the new name - ADCT): per the user, that row is left completely alone - no field changes, no detail/CUSIP fill - with the note `name already used by another row with this symbol (id N[, delisted]): NAME - nothing changed` (category `nameTaken`). Checked in `runStockMonitor` (not `planRow`) against every loaded row.
- Currency only when empty. Then, apply runs only: company details (`fillCompanyDetails`) for up to `MONITOR_DETAIL_LIMIT` (300) trading rows missing any, CUSIP for up to `MONITOR_CUSIP_LIMIT` (50) trading US rows - US first, newest first, so backfill progresses run by run; CUSIP lookups are paced `QOL_DELAY_MS` apart for quantumonline. `stock_symbol` is never changed automatically.
- **Stop**: `POST /api/monitor/stop` sets `stopRequested`; `runStockMonitor`'s `shouldStop()` is checked between quote batches, rows, detail fills and CUSIP lookups. A stop during the quote fetch writes **nothing** (`stoppedDuringQuotes`) - judging rows on incomplete quotes would mark every stock without a quote as delisted. A later stop keeps what was already written; the report carries `stopped` and `counts.checked` = rows actually processed. Restarting the server also ends a run (the user's first full run from the old UI was ended that way at ~2,500 of 79,381 rows); the CLI stops with Ctrl+C.
- On 2026-10-06 it was first applied to the tickers in the user's `Missing tickers.xlsx` (after a one-off script inserted the 308 of them that were missing and trading, same name/market rules as the add pre-fill).

**`lib/yahoo.js`** centralizes the `yahoo-finance2` client. `lookupStock(symbol)` returns `stock_symbol`/`company_name`/`exchange` (via `marketLabelForQuote(quote)`, which collapses Yahoo's finer-grained names like `NasdaqGS`/`NYSE American`/`OTC Markets OTCPK` to `NASDAQ`/`NYSE`/`AMEX`/`OTC` - `EXCHANGE_TO_MARKET` by code first, then a name-pattern fallback, anything unrecognized passes through as Yahoo's `fullExchangeName`) plus best-effort extended fields from `fetchCompanyDetails()` (`sector`, `industry`, `currency`, `company_location`, `urll`, `description`, `ceo` - via `quoteSummary`'s `assetProfile`/`price` modules; `ceo` is picked from `companyOfficers` by a "CEO"/"Chief Executive" title; `company_location` is a full postal address composed by `composeAddress()`, which skips missing pieces). `fetchCompanyDetails` never throws - a `quoteSummary` failure just leaves fields `null`. Yahoo doesn't expose CUSIP at all (licensed CUSIP Global Services data).

**Symbol format: always go through `toYahooSymbol()`.** US share classes and SPAC securities are written in exchange form (`BRK.B`, `KCA.U` units, `NE.W` warrants, `CELG.R` rights); Yahoo writes them `BRK-B`, `KCA-UN`, `NE-WT`, `CELG-RI`, and querying Yahoo with the exchange form returns nothing. `toYahooSymbol()` only rewrites a single-letter `.X` suffix, and leaves `.T` / `.L` / `.V` / `.F` alone (`YAHOO_MARKET_SUFFIXES` - Tokyo, London, TSXV, Frankfurt rows already in Yahoo form), so `000001.SZ`, `7203.T`, `BARC.L` pass through. A US class/security using one of those four letters would now not be converted - none was seen in the data. SEC's `company_tickers.json` uses the dash form (so `lib/cusipLookup.js` converts for the CIK lookup), but quantumonline.com uses the dot form - don't convert there.

**`fetchCompanyDetails(symbol, companyName)`'s foreign-listing fallback**: many thinly-traded US OTC tickers are a foreign company's cross-listing - `ULUCF` (Roland Mineral Enterprises) has nothing on Yahoo, but trades as `RME.V` on the TSXV, which Yahoo has full data for. When the direct lookup comes back with no *profile* (currency alone doesn't count - CHCRF returned only "USD" and used to skip the fallback to CHER.V), `findAlternateSymbol()` runs `yf.search(companyName)`, takes the top `EQUITY` result, and requires its name to match via `companyNamesMatch()` - a loose or absent match is "not found", never a guess. Only company details use this fallback; CUSIP lookup is tied to the original ticker.

**`lib/fillCompanyDetails.js`** wraps `fetchCompanyDetails` + the `UPDATE` (sanitizing text first) into `fillCompanyDetails(pool, stock)`, returning whether anything was written. `COALESCE(new, existing)` per field, so a field Yahoo doesn't return this time keeps its stored value. Shared by `scripts/fill-company-details.js` and the add auto-fill.

**`lib/cusipLookup.js`** holds the SEC-EDGAR-then-quantumonline.com CUSIP lookup behind `lookupCusip(symbol, { companyName, listing, onSourceError })` -> `{ cusip, source, reasons }`. It caches the SEC ticker->CIK map for the life of the process. Shared by `scripts/fill-cusip.js` and the add auto-fill. Past bugs shape it:
- **Only a 13G whose `SUBJECT COMPANY` header CIK is this company counts.** A company's EDGAR listing also holds 13Gs it filed *as a holder* of others; the old code stored another issuer's CUSIP for JPM, GS, MS, BLK, AMGN, CMCSA, ARCC and more. Self-filed accessions are skipped without downloading; at most `SEC_MAX_DOCS` documents are checked.
- **All SEC requests go through `secFetch()`**, spaced `SEC_MIN_GAP_MS` apart process-wide - SEC returned 429 to just 4 concurrent workers, then blocks for ~10 minutes.
- **The header subject isn't enough either**: filers mis-tag it (Norges Bank's 13G "about" PLUG is about Rubrik) and paste wrong CUSIPs (two of GROY's 13Gs print NexGen's). So the cover page's "(Name of Issuer)" must match the subject's names or `companyName`, and the result is a **vote by issuer (first 6 chars) across filings, then that issuer's newest CUSIP** - plain majority picked pre-split numbers (SMCI, HTZ). A lone 1-vs-1 disagreement is "not found". Placeholders like `000000000` are rejected by `isValidCusip`.
- **Some securities skip SEC entirely** (pass `listing` from `lib/nasdaqTrader.js`): preferreds/notes/warrants/units/rights (`isNonCommonSecurity` - SEC maps them to the parent's CIK, whose 13Gs are about the common), and any class of a multi-class company (`hasCommonSibling` - FOX/FOXA, UHAL/UHAL.B). quantumonline handles those, but is stale after reorganizations (NWS/NWSA, LBTYA/B/K, BATRK, FWONA/FWONK got pre-reorg CUSIPs).
- **Callers must run `findCusipConflict(pool, cusip, { stockId })` before writing**: quantumonline's pages carry other companies' CUSIPs (CSQR shows Copart's, TELO Outset's), which no name check can catch. A value another live row already holds is not written (logged instead) - it doesn't guess which side is right.
- quantumonline's no-match page says `Not Found!`; don't loosen that to `/not found/i` - bank pages contain "Not found in FDIC" next to a real CUSIP. Being keyed by ticker, a recycled ticker can return the *previous* issuer's CUSIP (FGC), so a quantumonline CUSIP is only trusted when the security name on the page contains the first distinctive word of `companyName` - pass `companyName` whenever known.
- SEC only lists the `SC 13G` form type; filings since late 2024 use the structured `SCHEDULE 13G` type, which this doesn't read. **Requires `SEC_EDGAR_CONTACT`** - SEC 403s automated requests without contact info; ask the user before hardcoding one, since it's their contact info going to a third party. quantumonline is a small site: `QOL_DELAY_MS` (default 500ms) paces bulk runs; don't lower it. SEC and quantumonline are US-only sources - non-US rows will come back "not found", which is expected.

**`lib/validateCusip.js`** implements the CUSIP check-digit algorithm (`isValidCusip`); `routes/stocks.js` rejects a malformed `cusips` on `POST`/`PUT` with a 400, and `lib/cusipLookup.js` sanity-checks parsed values with it.

**`lib/sanitizeText.js`** is the `Buffer.from(str,'utf8').toString('utf8')` round-trip that turns invalid/unpaired UTF-16 from external APIs into valid UTF-8 before it hits Postgres (which otherwise rejects the whole write). Used by `lib/applyStockUpdate.js` and `lib/fillCompanyDetails.js`. The 267 stocks' worth of data once lost to that error was most likely the Node v22.7.0 bug, not bad API text - keep calling it on new write paths, but the real protection is not running v22.7.0.

**`lib/nasdaqTrader.js`** loads NASDAQ Trader's daily symbol directory (`symbol -> { name (raw), exchange }`) for the `yahoo-lookup` pre-fill, CUSIP lookup and `scripts/audit-stocks.js`. **`lib/normalizeCompanyName.js`** (`normalizeCompanyName` - a lossy comparison fingerprint; `companyNamesMatch`; `issuerKey` / `isTruncationOf` / `sameCompany` for "do two sources mean the same issuer?") vs. **`lib/cleanSecurityName.js`** (strips a trailing " Common Stock" / " - Class A Ordinary Shares" etc. to produce a display name, at a word boundary so "Curtiss-Wright" survives) solve different problems - don't swap them.

**`scripts/`** are standalone CLI tools that talk to Postgres directly (each does its own `require('../db')` + `dotenv.config()`), independent of the running server. All of them use `lib/stockTable.js`; inserts skip a symbol that's already present instead of relying on `ON CONFLICT`, and there is no `source` column to stamp any more:
- `add-from-yahoo.js SYMBOL...` - look up and insert specific symbols (skipped if a live row has the symbol).
- `import-from-excel.js <path.xlsx>` - bulk insert from a spreadsheet (header aliases matched loosely; later duplicate rows win).
- `import-nasdaq-trader.js` - insert NASDAQ/NYSE/AMEX listings not yet present, names cleaned by `cleanSecurityName`. No OTC.
- `fill-company-details.js [SYMBOL...]` / `fill-cusip.js [SYMBOL...]` - backfill via the libs above. With no symbols they take every **non-delisted** row with a blank field - tens of thousands of rows in this table, many non-US (where SEC/quantumonline find nothing), so prefer passing symbols.
- `monitor-stocks.js [--apply] [--list] [SYMBOL...]` - the stock monitor from the CLI (see above).
- `audit-stocks.js [--out path.csv]` - **read-only** cross-check of live NASDAQ/NYSE/AMEX/OTC rows (other markets are skipped - the sources don't know them) against NASDAQ Trader's listing, SEC's `company_tickers.json` and Yahoo, writing `exports/audit-report.csv` (gitignored) for human review: symbol changes, delistings, truncated names, name mismatches (only when two sources agree against us). Apply findings via `applyStockUpdate`; mark delistings with `isdelisted = true`, never delete.
- `export-to-csv.js` - dumps the whole table to `exports/stocks.csv` (format in `lib/stockCsv.js`: real column names, incl. `companysite`, shared with `GET /api/stocks/export.csv`, which sends a UTF-8 BOM so Excel shows accented names). At ~79k rows with descriptions the file is ~9 MB, so `exports/` is gitignored - don't commit it. Descriptions contain newlines inside quoted fields, so count records with a CSV parser, not `wc -l`.
